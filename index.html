HOW I WORK WITH AI

AI와 일하는 방식

개발 사이클 단계마다 도구를 나눠 쓰고, 마지막 판단은 항상 직접 합니다.

분석 · 설계
Claude Code
규칙 문서(CLAUDE.md)를 기준으로 레거시 호출 경로·변경 이력을 정리하고 설계 대안을 교차 검증. DB 스키마는 문서 대신 MCP로 실시간 조회해 추측 없이 설계하고, 핵심 분기는 디버거로 재현해 확인.
구현 · 테스트
Claude Code · 서브에이전트
쿼리 작성·구조 개선 같은 작업은 역할별 서브에이전트에 위임하고 메인 흐름만 직접 운전. 테스트 초안 생성은 맡기되, 경계 조건과 검증 기준은 직접 설계.
리뷰
커스텀 skill · CodeRabbit
커밋 전 직접 만든 리뷰 skill이 리팩토링·코드리뷰·언어별 점검 에이전트를 순차 호출(신규 파일·대규모 수정 시 자동 트리거). PR 단계는 CodeRabbit이 한 번 더. 반복 지적은 규칙 문서로 흡수해 같은 지적이 안 나오게.

도구를 쓰는 데서 멈추지 않고, AI 워크플로우 자체를 엔지니어링합니다.

규칙 주입
컨벤션 문서
코딩 규칙·아키텍처 패턴을 규칙 문서로 명문화해 AI가 팀 스타일로 코딩하게 만듦. "이 코드베이스엔 안 맞는 일반론" 목록을 검증 일자와 함께 관리해 AI 리뷰의 false positive를 줄임.
가드레일
권한 · MCP 정책
실행 가능한 명령을 화이트리스트로 통제하고, DB MCP는 조회는 열되 DROP·DELETE는 차단. 생성 속도와 운영 안전을 동시에 확보.
컨텍스트 주입
조건부 참조 규칙
작업 유형을 인식하면 관련 가이드 문서를 먼저 읽고 착수하도록 규칙화. 휘발성 큰 정보는 문서에 박제하지 않고 그때그때 실측 — AI에게 "무엇을, 언제 참조할지"를 설계.
생성은 맡겨도, 검증은 맡기지 않는다.
